## Summary

Phase 13.1 makes three surgical improvements to the dipole calculator layer. The changes are
well-bounded: all three tasks touch the same `MACEDipoleCalculator` class, the same
`calculate_dipole_properties()` function, and the same `write_gaussian_output()` function —
with no changes to Gaussian input generation, energy calculator paths, or analysis code.

The autograd path (Task 1) is the most impactful change. It replaces 2×3N forward passes
through the dipole model with a single `get_dielectric_derivatives()` autograd call. For a
10-atom molecule (N=10), that drops from 60 model evaluations to 1 per Gaussian call. The
API is already implemented in `mace_dipole_core/calculators/mace.py` at line 387 and the
required tensor reshape is documented in CONTEXT.md. The polarizability passthrough (Task 2)
is straightforward: the model already returns a `(3,3)` polarizability tensor in Angstrom^3,
which must be converted to Bohr^3 (factor ~6.748) and flattened to 6 components in
lower-triangular order (xx, xy, yy, xz, yz, zz) for the Gaussian output line. The Raman
derivative passthrough (Task 3) requires a critical design clarification: the Gaussian external
output format does NOT have a slot for polarizability derivatives — the format is fixed as
energy/dipole, gradient, polarizability (6 values), dipole derivatives, Hessian. Therefore
`dalpha_dr` passthrough means threading it through the Python pipeline for future use only,
not writing it to the Gaussian file.

**Primary recommendation:** Implement all three improvements in a single call to
`get_dielectric_derivatives()` that extracts `dmu_dr`, the static polarizability, and
`dalpha_dr` simultaneously. Gate the polarizability and Raman extract on
`self.calc.models[0].use_polarizability` since these are only available for
`DipolePolarizabilityMACE` models.

## Architecture Patterns

### Recommended Change Structure

The three improvements compose naturally around a single `get_dielectric_derivatives()` call
that is added to `MACEDipoleCalculator`:

```
mace_loader.py              (primary change — new method + override)
  MACEDipoleCalculator
    + calculate_dipole_derivatives()   # override — autograd path
    + calculate_polarizability()        # new method

workflow.py                 (signature expansion)
  calculate_dipole_properties()        # returns 4-tuple not 3-tuple
  run_next_calculation()               # threading dalpha_dr through (store on object or pass)

gaussian/io.py              (write real polarizability)
  write_gaussian_output()              # accept polarizability arg, convert + write
```

### Pattern 1: Autograd Override

Override `calculate_dipole_derivatives()` in `MACEDipoleCalculator`. The base class
`DipoleCalculatorBase.calculate_dipole_derivatives()` does 2×3N forward passes; the override
calls `get_dielectric_derivatives()` once.

```python
# Source: mace_dipole_core/calculators/mace.py:387-420

def calculate_dipole_derivatives(self, atoms, **kwargs) -> np.ndarray:
    """Use autograd instead of finite differences — ~20-60x faster."""
    self._ensure_calculator()
    result = self.calc.get_dielectric_derivatives(atoms)
    # result is dmu_dr if use_polarizability=False,
    # or (dmu_dr, dalpha_dr) tuple if use_polarizability=True
    if isinstance(result, tuple):
        dmu_dr = result[0]   # shape (3, N_atoms, 3)
    else:
        dmu_dr = result      # shape (3, N_atoms, 3)
    # Reshape: (3, N_atoms, 3) -> (3*N_atoms, 3)
    # transpose(1, 2, 0) -> (N_atoms, 3, 3), but we need (3*N_atoms, 3)
    # Correct: transpose(0,1,2) stays (3,N,3) -> reshape needs (N*3,3)
    # Per CONTEXT.md decision: dmu_dr.transpose(1, 2, 0).reshape(3*N_atoms, 3)
    # Note: transpose(1,2,0) swaps axes: (3,N,3) -> (N,3,3) -> reshape to (3N,3) ✓
    N_atoms = len(atoms)
    return dmu_dr.transpose(1, 2, 0).reshape(3 * N_atoms, 3)
```

**Shape walkthrough (confirmed from source):**
- `compute_dielectric_gradients` uses `vmap` over `I_N = eye(3)`, returns `(3, N_atoms, 3)`:
  axis-0 = dipole component (x/y/z), axis-1 = atom index, axis-2 = spatial displacement
- Required for `write_gaussian_output`: `(3*N_atoms, 3)` where row `3i+j` is derivative of
  dipole w.r.t. displacement of atom `i` in direction `j`
- `transpose(1, 2, 0)` reorders `(3, N, 3) -> (N, 3, 3)` then `reshape(3N, 3)` gives the
  correct `(3N, 3)` layout (each row is dmu/dr_{atom,dir})

### Pattern 3: Polarizability to Gaussian Format

The model returns polarizability as a `(3, 3)` array in **Angstrom^3** (confirmed from
`mace_dipole_core/data/utils.py:43` comment: `polarizability: ... # Angstrom^3`).

Gaussian's external output expects polarizability in **Bohr^3** as 6 values in lower-
triangular order: `[αxx, αxy, αyy, αxz, αyz, αzz]` — written on 2 lines of 3 each.

```python
# Conversion and extraction
ANGSTROM3_TO_BOHR3 = (1.0 / BOHR_TO_ANGSTROM) ** 3  # ≈ 6.748

def _polarizability_to_voigt6(polar_3x3: np.ndarray) -> np.ndarray:
    """Convert (3,3) array in Angstrom^3 to 6-component Voigt vector in Bohr^3."""
    p = polar_3x3 * ANGSTROM3_TO_BOHR3
    return np.array([p[0,0], p[0,1], p[1,1], p[0,2], p[1,2], p[2,2]])
    # = [xx, xy, yy, xz, yz, zz] — lower triangular order
```

**Confirmed lower-triangular order** from Gaussian documentation: αxx, αxy, αyy, αxz, αyz, αzz.
The current `io.py` code already writes 6 zeros in this layout — the only change is accepting
a real value and converting units.

### Pattern 4: How to Extract Static Polarizability

**Design clarification needed:** `get_dielectric_derivatives()` runs the full forward pass
to compute `dmu_dr` and `dalpha_dr` but does not directly return the static polarizability
tensor in its return value. The static polarizability is available via
`atoms_copy.get_polarizability()` (via ASE `calculate()` path) after attaching the calc.

Two approaches:
1. Call `get_dielectric_derivatives()` for derivatives, then separately call
   `atoms_copy.get_polarizability()` for the static value. Two forward passes conceptually,
   but `get_dielectric_derivatives()` already triggers a full forward pass; `get_polarizability()`
   just reads `self.results["polarizability"]` if already computed.
2. Use a single `calculate()` call that populates both `results["polarizability"]` and
   uses `compute_dielectric_derivatives=True` (internal model path). This requires calling
   the model directly.

**Simpler approach (recommended):** Call `get_dielectric_derivatives()` for `dmu_dr`/`dalpha_dr`,
then immediately call `self.calc.results.get("polarizability")` — `get_dielectric_derivatives()`
performs a full forward pass and the `calculate()` method on the ASE calculator will have
populated `self.results["polarizability"]` if `model_type == "DipolePolarizabilityMACE"`.

**However:** note that `calculate()` in `mace_dipole_core/calculators/mace.py` lines 290-292
has the polarizability result commented out:
```python
#if self.model_type == "DipolePolarizabilityMACE":
#    ret_tensors["polarizability"][i] = out["polarizability"].detach()
#    ret_tensors["polarizability_sh"][i] = out["polarizability_sh"].detach()
```
This means the regular ASE `calculate()` path does NOT populate `results["polarizability"]`.
The static polarizability must be extracted via a separate model call (or by accessing the
model output directly from within `get_dielectric_derivatives()`).

**Recommended implementation:** Add a `calculate_polarizability(atoms)` method that calls
`self.calc.models[0]` directly (single model call, no committee averaging needed for this
phase since the production model has `num_models == 1`):

```python
def calculate_polarizability(self, atoms) -> np.ndarray:
    """Extract static polarizability in Angstrom^3, shape (3,3). Returns zeros if not available."""
    self._ensure_calculator()
    if not self.calc.models[0].use_polarizability:
        return np.zeros((3, 3))
    # get_dielectric_derivatives performs the forward pass with compute_dielectric_derivatives=True
    # which also computes total_polarizability in the model forward. We need to access it.
    # Since get_dielectric_derivatives() does not expose it, call the model directly:
    batch = self.calc._atoms_to_batch(atoms)
    output = self.calc.models[0](
        self.calc._clone_batch(batch).to_dict(),
        compute_dielectric_derivatives=False,
        training=False,
    )
    polar = output["polarizability"]   # shape (1,3,3) — 1 graph
    return polar[0].detach().cpu().numpy()  # shape (3,3) in Angstrom^3
```

**Alternatively (cleaner):** The CONTEXT.md specifies `calculate_polarizability(atoms)` as a
method added to `MACEDipoleCalculator`. A separate small forward pass is acceptable since
polarizability extraction only happens once per ZMQ call (not in the hot loop of derivatives).

### Anti-Patterns to Avoid

- **Silent fallback on autograd failure:** CONTEXT.md explicitly requires letting exceptions
  propagate. Do not wrap `get_dielectric_derivatives()` in a try/except that falls back to
  finite differences.
- **Calling `get_dielectric_derivatives()` twice:** Call once, unpack both `dmu_dr` and
  `dalpha_dr` from the same call. Do not call it once for derivatives and once for dalpha.
- **Writing dalpha_dr to the Gaussian file:** The Gaussian external output format has no slot
  for polarizability derivatives. Writing extra data would corrupt the file. See Critical Finding below.

## Common Pitfalls

### Pitfall 1: Wrong `dmu_dr` Shape Interpretation

**What goes wrong:** Transposing or reshaping `dmu_dr` incorrectly so that dipole components
map to wrong atoms/directions. The test assertion (autograd ≈ finite difference) will catch
this, but only if the sanity check is implemented.

**Why it happens:** `dmu_dr` has shape `(3, N_atoms, 3)` with axes meaning
`(dipole_component, atom, spatial_dir)`. To get `(3*N_atoms, 3)` where each row is
`dmu/d(atom_i, dir_j)` — i.e., "change in full dipole vector for displacement of atom i in
direction j" — the correct transpose is `(1, 2, 0) -> (N, 3, 3)` then reshape to `(3N, 3)`.
The WRONG approach would be `transpose(0, 2, 1)` (swaps spatial dims) or a bare `reshape`
without transpose.

**How to avoid:** Run autograd and finite-difference on water (3 atoms = 9 rows) and compare
matrices element-wise with `np.allclose(tol=1e-4)`.

**Warning signs:** Non-symmetric IR intensities for symmetric molecules (e.g. CH4 should have
degenerate modes with equal intensities).

### Pitfall 2: Model Does Not Have `use_polarizability=True`

**What goes wrong:** `get_dielectric_derivatives()` returns only `dmu_dr` (a numpy array,
not a tuple) when `model.use_polarizability = False`. Code that unconditionally unpacks as
`dmu_dr, dalpha_dr = result` will crash with `too many values to unpack` or wrong assignment.

**Why it happens:** The pretrained model `model_1_dipole.model` is loaded as
`DipolePolarizabilityMACE` — check whether it has `use_polarizability=True` at runtime.
This is a model-file-specific attribute.

**How to avoid:**
```python
use_polar = self.calc.models[0].use_polarizability
if use_polar:
    dmu_dr, dalpha_dr = self.calc.get_dielectric_derivatives(atoms)
else:
    dmu_dr = self.calc.get_dielectric_derivatives(atoms)
    dalpha_dr = None
```

**Warning signs:** `ValueError: too many values to unpack` or unexpected `None` for
dalpha_dr downstream.

### Pitfall 3: Polarizability Units

**What goes wrong:** Writing polarizability in Angstrom^3 to Gaussian, which expects Bohr^3.
The factor is ~6.748x — Gaussian's freq output polarizability will be ~7x too small.

**Why it happens:** `mace_dipole_core/data/utils.py:43` documents the training data unit as
Angstrom^3. The model inherits those units. Gaussian external interface docs do not specify
units explicitly in the format description, but atomic units (Bohr^3) is standard for Gaussian.

**How to avoid:** Apply `ANGSTROM3_TO_BOHR3 = (ANGSTROM_TO_BOHR)**3 ≈ 6.748` before writing.
Verify: for water, the static polarizability should be ~9-10 Bohr^3 (literature: ~9.64 Bohr^3).

**Warning signs:** Gaussian reports anomalously small polarizability values in output.

### Pitfall 4: Raman Derivatives Cannot Go Into Gaussian External Output

**What goes wrong:** Attempting to write `dalpha_dr` into the Gaussian external output file
corrupts the file — Gaussian will fail or produce wrong results.

**Why it happens:** The Gaussian external output format is fixed:
  1. energy + dipole (1 line)
  2. gradient (N lines)
  3. polarizability — 6 values (2 lines)
  4. dipole derivatives (3N lines)
  5. Hessian (lower triangular, present only at deriv=2)

There is NO slot for polarizability derivatives in this format (confirmed from Gaussian docs
and the g09/k_external.htm reference). The format stops after dipole derivatives + Hessian.

**How to avoid:** Store `dalpha_dr` in the Python pipeline (e.g., return it from
`calculate_dipole_properties()`) for future use, but do NOT write it to the Gaussian output
file. The "passthrough" in CONTEXT.md means threading through Python data structures only.

**Warning signs:** Gaussian exits with error about malformed external output.

### Pitfall 5: `calculate()` Does Not Populate `results["polarizability"]`

**What goes wrong:** Calling `self.calc.results.get("polarizability")` after
`get_dielectric_derivatives()` returns `None` because the standard `calculate()` path
has the polarizability lines commented out in `mace_dipole_core/calculators/mace.py:290-292`.

**Why it happens:** The calculator's `calculate()` method has a commented-out block that
should populate `results["polarizability"]` but doesn't. This is a known bug/TODO in the
dipole fork.

**How to avoid:** Call the model directly (or call `get_dipole_moment()` / a separate small
forward pass) rather than relying on `self.calc.results["polarizability"]`.

## Gaussian External Output Format (Critical Reference)

The Gaussian `External=` output file format is fixed and has exactly these sections
(confirmed from g09/k_external.htm via https://thiele.ruc.dk/~spanget/help/g09/k_external.htm):

| Section | Format | Lines | When Present |
|---------|--------|-------|--------------|
| Energy + dipole | `4D20.12` | 1 | Always |
| Gradient | `3D20.12` | N atoms | If deriv >= 1 |
| Polarizability (6 components) | `3D20.12` | 2 | If deriv >= 1 |
| Dipole derivatives | `3D20.12` | 3*N | If deriv >= 1 |
| Hessian (lower triangular) | `3D20.12` | varies | If deriv >= 2 |

**There is no section for polarizability derivatives (dalpha_dr).** Gaussian's external
protocol was designed before Raman-via-external was a use case. The `dalpha_dr` passthrough
is therefore Python-pipeline-only (store in data structures, return from functions) — it
cannot be passed to Gaussian 16 through the external interface.

Polarizability 6-component order: **αxx, αxy, αyy, αxz, αyz, αzz** (lower triangular,
i.e. `[0,0], [0,1], [1,1], [0,2], [1,2], [2,2]`).
