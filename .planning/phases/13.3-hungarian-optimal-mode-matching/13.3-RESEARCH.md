## Summary

This phase replaces the greedy mode matching algorithm in `match_modes()` with the Hungarian algorithm via `scipy.optimize.linear_sum_assignment`. The current greedy approach independently assigns each ML mode to its highest-overlap DFT mode, which allows duplicate assignments (two ML modes claiming the same DFT mode). The Hungarian algorithm finds the globally optimal bijective assignment that maximizes total overlap.

The change is small in code volume (~10 lines in `match_modes()`) but significant in correctness. The existing `create_alignment_matrix()` already builds the full overlap matrix needed as input. `scipy` 1.15.3 is already installed and `linear_sum_assignment` natively supports rectangular matrices (unequal mode counts). Additional work includes wiring Hungarian matches into heatmap borders, differentiating low-overlap pairs in regression plots, and handling unmatched modes when mode counts differ.

**Primary recommendation:** Use `scipy.optimize.linear_sum_assignment(-overlap_matrix)` (negate to maximize), reuse `create_alignment_matrix()` for the cost matrix, keep the existing return type with `None` for unmatched modes.

### Pattern 1: Hungarian Assignment via linear_sum_assignment

**What:** Replace greedy per-row argmax with globally optimal bijective assignment.

**Implementation:**
```python
from scipy.optimize import linear_sum_assignment

def match_modes(
    modes_calc: np.ndarray, modes_ref: np.ndarray, threshold: float = 0.5
) -> dict[int, tuple[int | None, float]]:
    n_calc = modes_calc.shape[0]
    n_ref = modes_ref.shape[0]

    # Build full overlap matrix using existing function
    overlap_matrix = create_alignment_matrix(modes_calc, modes_ref)

    # Hungarian assignment: negate overlap to convert max-overlap to min-cost
    row_ind, col_ind = linear_sum_assignment(-overlap_matrix)

    matches: dict[int, tuple[int | None, float]] = {}

    # Record matched pairs
    for r, c in zip(row_ind, col_ind):
        overlap = overlap_matrix[r, c]
        matches[r] = (c, overlap)
        if overlap < threshold:
            logger.warning(f"Mode {r:3d} -> Ref mode {c:3d} (low overlap: {overlap:.4f})")
        else:
            logger.debug(f"Mode {r:3d} -> Ref mode {c:3d} (overlap: {overlap:.4f})")

    # Handle unmatched calc modes (when n_calc > n_ref)
    for i in range(n_calc):
        if i not in matches:
            matches[i] = (None, 0.0)
            logger.warning(f"Mode {i:3d} -> No match (more calc modes than ref modes)")

    return matches
```

**Key details:**
- `linear_sum_assignment` on a rectangular (n_calc x n_ref) matrix returns indices of length `min(n_calc, n_ref)`. When n_calc > n_ref, some calc modes are unassigned. When n_ref > n_calc, some ref modes are unassigned (but we only track calc->ref mapping).
- Negating the overlap matrix converts maximization to minimization (scipy minimizes by default).
- The return type stays `dict[int, tuple[int | None, float]]` -- the only change is `int | None` instead of `int` for the ref index to accommodate unmatched modes.

**Key detail:** The heatmap uses `origin="lower"`, so cell (i, j) in matrix space maps to pixel position `(j - 0.5, i - 0.5)` for the rectangle corner. The `imshow` with `origin="lower"` means row 0 is at the bottom.

### Pattern 3: Regression Plot Marker Differentiation

**What:** Show low-overlap pairs with open circles instead of filled markers.

**Approach:** The `plot_regression` method receives `mode_mapping` but not `mode_overlaps`. To differentiate markers, `mode_overlaps` must also be passed through. Then scatter in two groups:

```python
# Split matched points into confident vs uncertain
confident_mask = np.array([
    mode_overlaps.get(ml_idx, 1.0) >= 0.5
    for ml_idx in matched_ml_indices
]) if mode_overlaps is not None else np.ones(len(dft_freq), dtype=bool)

# Confident matches: filled markers (existing style)
ax1.scatter(dft_freq[confident_mask], ml_freq[confident_mask],
            c=POINT_COLOR, s=80, alpha=0.7, edgecolors="white", linewidth=1.5, zorder=3)

# Uncertain matches: open circles
if not np.all(confident_mask):
    ax1.scatter(dft_freq[~confident_mask], ml_freq[~confident_mask],
                facecolors="none", edgecolors=POINT_COLOR, s=80, alpha=0.7,
                linewidth=1.5, zorder=3, label="Low-overlap match")
```

**Complexity note:** The `match_by_mode` function remaps mode IDs and the overlap information gets lost in the process. Getting per-point overlap into the scatter plot requires threading `mode_overlaps` through `plot_regression` and correlating it with the matched points. This is the most intricate part of the phase.

### Anti-Patterns to Avoid
- **Do NOT pad the overlap matrix to make it square.** `linear_sum_assignment` handles rectangular matrices natively since scipy 1.4.0. Padding wastes computation and creates phantom matches.
- **Do NOT filter negative frequencies before matching.** Negative frequencies (imaginary modes from unconverged geometries) are valid data points per project convention. They should participate in matching so they pair correctly rather than shifting all indices.
- **Do NOT change the return type to include unmatched ref modes.** The existing interface is calc_idx -> (ref_idx, overlap). Unmatched ref modes are implicit (not in any value). Changing to bidirectional would break both call sites.

## Common Pitfalls

### Pitfall 1: Forgetting to Negate the Overlap Matrix
**What goes wrong:** `linear_sum_assignment` minimizes cost. Passing the overlap matrix directly finds the WORST matching (minimum total overlap).
**How to avoid:** Always pass `-overlap_matrix` as the cost matrix.
**Warning signs:** All matched pairs have low overlap; previously-good matches get worse.

### Pitfall 2: Type Annotation Breaking Downstream
**What goes wrong:** Changing return type from `tuple[int, float]` to `tuple[int | None, float]` breaks `mode_mapping` construction at `analysis_workflow.py:364` which unpacks assuming int.
**How to avoid:** Guard the unpacking: `for ml_idx, (dft_idx, overlap) in matches.items(): if dft_idx is not None: mode_mapping[ml_idx] = dft_idx`
**Warning signs:** TypeError when n_calc != n_ref.

### Pitfall 3: Heatmap Rectangle Coordinates with origin="lower"
**What goes wrong:** Rectangle coordinates are placed wrong because `origin="lower"` flips the y-axis.
**How to avoid:** Rectangle at `(col - 0.5, row - 0.5)` works correctly with `origin="lower"` because imshow maps matrix[row, col] to (col, row) in axes coordinates, and origin="lower" means row 0 is at the bottom (which is already the default axes direction).
**Warning signs:** Borders appear on wrong cells.

### Pitfall 4: mode_overlaps Not Reaching plot_regression
**What goes wrong:** `plot_regression` currently only takes `mode_mapping`. Adding marker differentiation requires `mode_overlaps` to also flow through.
**How to avoid:** Add `mode_overlaps` parameter to `plot_regression` and pass it from `analysis_workflow.py:470`.
**Warning signs:** All markers look the same despite some having low overlap.

### Pitfall 5: Existing Tests Assuming Non-None ref_idx
**What goes wrong:** Existing tests like `test_match_modes_identity` unpack `matches[i]` as `(ref_idx, overlap)` and assert `ref_idx == i`. If unequal mode counts produce None entries, tests might fail.
**How to avoid:** Existing tests use equal-sized mode arrays, so None entries won't appear. Only add None-handling tests for new rectangular test cases.

### Bijection Test Case (Greedy Failure Scenario)
```python
def test_hungarian_prevents_duplicate_assignment():
    """Two calc modes both closest to the same ref mode under greedy,
    but Hungarian gives correct 1-to-1 mapping."""
    # 3 atoms, 3 modes
    modes_ref = np.zeros((3, 3, 3))
    modes_ref[0, 0, 0] = 1.0  # Ref mode 0: pure x on atom 0
    modes_ref[1, 1, 1] = 1.0  # Ref mode 1: pure y on atom 1
    modes_ref[2, 2, 2] = 1.0  # Ref mode 2: pure z on atom 2

    modes_calc = np.zeros((3, 3, 3))
    # Calc mode 0: mostly ref mode 0, slight ref mode 1
    modes_calc[0, 0, 0] = 0.9
    modes_calc[0, 1, 1] = 0.1
    # Calc mode 1: also mostly ref mode 0, but less so
    modes_calc[1, 0, 0] = 0.7
    modes_calc[1, 1, 1] = 0.5
    # Calc mode 2: clearly ref mode 2
    modes_calc[2, 2, 2] = 1.0

    matches = match_modes(modes_calc, modes_ref, threshold=0.3)

    # Greedy would assign both calc 0 and calc 1 to ref 0
    # Hungarian should assign calc 0 -> ref 0, calc 1 -> ref 1
    assigned_refs = [matches[i][0] for i in range(3)]
    assert len(set(assigned_refs)) == 3, "All assignments should be unique (bijective)"
    assert matches[2][0] == 2, "Calc mode 2 should match ref mode 2"
```
