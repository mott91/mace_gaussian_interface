# Phase 13.5: MACE-POLAR-1 Energy Calculator - Context

**Gathered:** 2026-03-16
**Status:** Ready for planning

<domain>
## Phase Boundary

Integrate MACE-POLAR-1 as a new energy calculator option (`mace_polar`) in the CLI and workflow pipeline. It adds long-range electrostatics (trained on OMol25, 100M structures, 83 elements) which may improve geometries for large/polar molecules. Wire into `--energy-calculators` and `--optimization-calculator` CLI options following the established calculator expansion pattern from Phase 13.

</domain>

<decisions>
## Implementation Decisions

### mace-torch version requirement
- Upgrade mace-torch from 0.3.14 to main branch (`pip install git+https://github.com/ACEsuit/mace.git@main`)
- `mace_polar()` exists on main but is NOT in any PyPI release (not even 0.3.15)
- Run existing test suite after upgrade to verify no regressions in mace_mp/mace_off/mace_omol/mace_anicc

### Model loading API
- `from mace.calculators import mace_polar`
- Call: `mace_polar(model="polar-1-l", device="cuda", default_dtype="float64")`
- Upstream default is `float32` but we override to `float64` for consistency with all other calculators in the pipeline
- Upstream default model is `polar-1-m` but we use `polar-1-l` (large) to match quality preference (mace_mp/mace_off use "large", mace_omol uses "extra_large")
- Model auto-downloads on first use (same as mace_mp/mace_off/mace_omol)
- `model_type="PolarMACE"` is set internally by `mace_polar()` — no need to pass it
- No `dispersion=False` parameter (unlike mace_mp/mace_off/mace_omol)

### CLI naming
- CLI name: `mace_polar` (follows mace_mp/mace_off/mace_omol/mace_anicc convention)
- Add to `VALID_ENERGY_CALCULATORS` list in `cli.py`
- Add to `--optimization-calculator` click.Choice list
- Do NOT change the default optimization calculator (keep `mace_omol`)

### Element support
- 83 elements — broad support, no element guard needed (unlike mace_anicc's HCNO restriction)

### Result directory naming
- Follows existing `{energy}_{dipole}` convention: `mace_polar_espaloma/`, `mace_polar_mace_ml/`

### DFT baseline
- Add `mace_polar` entry to `DFT_BASELINES` dict in `dft_baseline.py` with appropriate method/basis

### Claude's Discretion
- Exact error handling if mace_polar import fails (mace-torch version too old)
- Whether to add a version check or just let ImportError surface naturally
- Test approach (mock vs. integration for the new calculator branch)

</decisions>

<specifics>
## Specific Ideas

- Thesis angle: MACE-POLAR-1 adds long-range electrostatics that other MACE models lack. If it improves geometries for polar molecules (water, ammonia, acetic acid) but not non-polar ones (alkanes), that's a clean thesis result about the importance of electrostatics in IR spectroscopy.
- The model is trained on OMol25 (100M structures) — same dataset as MACE-OMOL but with added polarization physics.

</specifics>
