**Researched:** 2026-04-11

## Summary

Phase 23 is an **HTML generator refactor**, not a compute-pipeline change. Every piece of data it needs — Lorentzian spectra (`SpectrumAnalyzer.broaden_spectrum`), experimental traces (`ExperimentalSpectrum`), degenerate-mode metadata (`DegenerateGroupResult`), timing breakdowns (`ml_gaussian_timing` / `dft_gaussian_timing`), and hardware info — is **already in the comparison dict** constructed by `ComparisonWorkflow.run_single_comparison`. No new data flow is needed upstream; we re-route existing data into Plotly JSON instead of base64 PNGs.

The dominant technical risk is the **Plotly bundling tradeoff**: embedding plotly.js inline inflates one report from ~500 KB to ~4.8 MB (verified: `include_plotlyjs='inline'` returned 4,838,186 bytes in my test vs. 7,471 bytes for CDN). The recommended path is `include_plotlyjs='cdn'` for the default self-contained report and an opt-in `--offline` flag that emits `include_plotlyjs=True`. D-06 says "bundled" but the user's Claude-discretion note explicitly allows CDN "as long as report is self-contained" — CDN files are still one-file self-contained for anyone with internet, which is the normal thesis-review use case.

The class overhaul is simpler than it looks: `HTMLReportGenerator.generate_report` is one orchestration method that calls ~8 section builders; each builder is independent and can be migrated to Plotly one at a time. The mode-aware split (D-05) is a trivial `mode: Literal["harmonic", "anharmonic"]` ctor flag plus conditional inclusion of overtone/combination sections — no subclassing needed.

**Primary recommendation:** Keep `HTMLReportGenerator` as the single class. Add `mode` and `plotly_js` constructor flags. Replace each `create_*_section` that embeds a PNG with one that calls a new `_plotly_spectrum_div(ml_spec, dft_spec, experimental)` / `_plotly_regression_div(...)` / `_plotly_heatmap_div(...)` helper. Heatmaps stay as static PNGs (already rendered by `plot_mode_overlap_heatmap`, no added value from interactivity for an NxN matrix of small molecules). Emit a `report_data.json` sibling to `report.html` with the canonical schema documented below.

### Pattern 1: Plotly Figure Builder (pure function)
**What:** A function takes already-computed numpy arrays and returns `plotly.graph_objects.Figure`. No I/O, no side effects.
**When to use:** Every plot type that becomes interactive.
**Example:**
```python
# Source: pattern verified against plotly 6.3.1 docs [VERIFIED: micromamba run to_html]
import plotly.graph_objects as go
import numpy as np

def build_spectrum_figure(
    freq_grid: np.ndarray,
    dft_norm: np.ndarray,
    ml_norm: np.ndarray,
    ml_name: str,
    experimental_norm: np.ndarray | None = None,
    offset: float = 1.5,
) -> go.Figure:
    """Reproduces plot_spectra_comparison() as an interactive Plotly figure.

    Preserves Phase 18's DFT-above / ML-below-with-offset convention.
    Experimental trace (Phase 21 convention) is a dashed gray line at y=0.
    """
    fig = go.Figure()
    fig.add_trace(go.Scatter(
        x=freq_grid, y=dft_norm,
        name="DFT (anharmonic)",
        line=dict(color="#2E3440", width=2),
        hovertemplate="%{x:.1f} cm⁻¹<br>Absorbance: %{y:.3f}<extra>DFT</extra>",
    ))
    fig.add_trace(go.Scatter(
        x=freq_grid, y=ml_norm + offset,
        name=f"ML ({ml_name})",
        line=dict(color="#88C0D0", width=2),
        hovertemplate="%{x:.1f} cm⁻¹<br>Absorbance: %{y:.3f}<extra>ML</extra>",
    ))
    if experimental_norm is not None:
        fig.add_trace(go.Scatter(
            x=freq_grid, y=experimental_norm,
            name="Experimental (NIST)",
            line=dict(color="#888888", width=1, dash="dash"),
            hovertemplate="%{x:.1f} cm⁻¹<br>Absorbance: %{y:.3f}<extra>Exp.</extra>",
        ))
    fig.update_layout(
        xaxis_title="Wavenumber (cm⁻¹)",
        yaxis_title="Absorbance (normalized)",
        xaxis=dict(autorange="reversed"),  # spectroscopic convention: high freq on left
        hovermode="x unified",
        template="simple_white",
        height=500,
        margin=dict(l=60, r=20, t=40, b=50),
    )
    return fig
```

**Note — spectroscopic convention:** IR spectra are conventionally plotted with wavenumber *decreasing* left-to-right. The current matplotlib code does NOT do this (`ax1.set_xlim(self.freq_range)` is ascending). This is a good moment to fix it; confirm with user in UI phase.

- **Don't generate matplotlib PNG and Plotly side-by-side.** D-08 says replace, not add. Per-method spectrum/regression become Plotly only. Heatmaps stay PNG (existing generator is fine).

## Common Pitfalls

### Pitfall 1: Plotly CDN version drift
**What goes wrong:** Plotly Python library updates bundled plotly.js version. Reports generated last year may reference `plotly-2.x.min.js` which CDN no longer serves or which has API breakage with older fig JSON.
**Why it happens:** `include_plotlyjs='cdn'` emits a URL pinned to the currently-installed Python library's bundled JS (verified: 6.3.1 → plotly-3.1.1.min.js).
**How to avoid:** Lower-bound `plotly>=5.20` in pyproject; the CDN URL gets baked into the HTML at generation time, so old reports keep working as long as Plotly CDN retains old versions (it does — Plotly keeps all 1.x and 2.x online).
**Warning signs:** Reports render as blank page → check browser console for script load error.

### Pitfall 2: File size blowout with `include_plotlyjs=True`
**What goes wrong:** `plotly.io.to_html(fig, include_plotlyjs=True)` embeds plotly.js on **every call**. If you call it once per plot (say, 10 per report), you get 10 × 4.8 MB = 48 MB HTML file that Chrome chokes on.
**Why it happens:** Plotly docs wording is ambiguous; each `to_html` call is standalone.
**How to avoid:** Only the FIRST figure uses `include_plotlyjs='cdn'` (or `'inline'` if offline). All subsequent figures use `include_plotlyjs=False`. The generator must track this:
```python
self._plotlyjs_emitted = False
def _plot_html(self, fig) -> str:
    if not self._plotlyjs_emitted:
        self._plotlyjs_emitted = True
        return pio.to_html(fig, include_plotlyjs=self.plotly_js, full_html=False)
    return pio.to_html(fig, include_plotlyjs=False, full_html=False)
```
**Warning signs:** Report > 10 MB → multiple copies of plotly.js embedded.

### Pitfall 3: Degenerate-mode groups disappearing from the report
**What goes wrong:** Current generator has a de-duplication loop (line 889–892 of analysis_workflow.py) that adds groups from the FIRST comparison only (`break` after first). If the refactor rewrites this, the bug-or-feature might become a bug — overtone sections in the anharmonic report expect groups to be available.
**Why it happens:** Groups come from the DFT reference and are identical across ML comparisons, so dedup-by-first is correct; but easy to break during refactor.
**How to avoid:** Keep the existing dedup behavior verbatim in the new generator. Add a test: assert `len(report.degenerate_groups) == len(dft_deg_result.groups)` after report construction.
**Warning signs:** Per-method section shows degenerate info, but executive summary doesn't.

### Pitfall 4: Experimental overlay normalization inconsistency
**What goes wrong:** Current matplotlib code interpolates experimental onto `self.freq_grid`, then re-normalizes to `[0, 1]`. If Plotly builder does its own normalization on raw `experimental.wavenumbers`, the two reports (harmonic vs anharmonic) show slightly different experimental curves → visual inconsistency.
**Why it happens:** Two code paths, same data, different preprocessing.
**How to avoid:** Move the "experimental onto analyzer.freq_grid with normalization" logic into a single helper `_experimental_on_grid(exp, freq_grid) -> np.ndarray` and call it from both the Plotly builder and any legacy matplotlib path that still exists for testing.
**Warning signs:** Peak heights in harmonic report don't match peak heights in anharmonic report at the same wavenumber.

### Pitfall 5: Tests under `tests/` run without network — NIST fetcher must not be live-called
**What goes wrong:** Test for new report generator uses a real `ExperimentalSpectrum` object, triggers NIST fetch on every run.
**How to avoid:** Use the `_parse_jdx_file(jdx_path)` entry point with a cached JDX fixture, or construct `ExperimentalSpectrum(wavenumbers=..., absorbance=..., ...)` directly in test. `fetch_experimental_spectrum` is the only network-hitting function.
**Warning signs:** Tests hang on offline machines.

### Example 2: Executive summary verdict algorithm (D-02, Claude discretion)
```python
# Source: new file mace_gaussian/analysis/executive_summary.py
from typing import Optional
import numpy as np
from scipy.stats import pearsonr

def compute_experimental_agreement(
    ml_broadened: np.ndarray,
    exp_on_grid: np.ndarray,
) -> float:
    """Pearson correlation of broadened ML spectrum vs experimental on common grid.

    Returns value in [0, 1] (negative correlations clipped to 0 since they're
    physically meaningless for spectra).
    """
    if exp_on_grid is None or np.allclose(exp_on_grid, 0):
        return float("nan")
    r, _ = pearsonr(ml_broadened, exp_on_grid)
    return float(max(0.0, r))

def rank_methods(comparisons: list[dict], weights: dict | None = None) -> list[dict]:
    """Composite score. Lower is better.

    Default weights (Claude discretion per CONTEXT.md):
    - 40% RMSE (primary accuracy metric)
    - 30% (1 - R²_freq)  (linearity of correlation)
    - 20% (1 - R²_intensity) (intensity accuracy)
    - 10% (1 - experimental_agreement) when experimental available; else 0
      and redistribute to RMSE weight
    """
    weights = weights or {"rmse": 0.4, "r2_freq": 0.3, "r2_int": 0.2, "exp": 0.1}
    has_exp = any(not np.isnan(c.get("experimental_agreement", float("nan")))
                  for c in comparisons)
    if not has_exp:
        weights = {"rmse": 0.5, "r2_freq": 0.3, "r2_int": 0.2, "exp": 0.0}

    # Normalize RMSE across the competing methods (z-score within this molecule)
    rmses = np.array([c["metrics"].rmse_freq for c in comparisons])
    rmse_min, rmse_max = rmses.min(), rmses.max()
    rmse_norm = (rmses - rmse_min) / max(rmse_max - rmse_min, 1e-9)

    scored = []
    for c, rn in zip(comparisons, rmse_norm):
        m = c["metrics"]
        exp_agree = c.get("experimental_agreement", 0.0)
        if np.isnan(exp_agree):
            exp_agree = 0.0
        score = (
            weights["rmse"] * rn
            + weights["r2_freq"] * (1.0 - m.r2_freq)
            + weights["r2_int"] * (1.0 - m.r2_intensity)
            + weights["exp"] * (1.0 - exp_agree)
        )
        scored.append({
            "name": c["name"],
            "composite_score": float(score),
            "r2_freq": m.r2_freq,
            "r2_intensity": m.r2_intensity,
            "rmse_freq": m.rmse_freq,
            "speedup": c["speedup"],
            "experimental_agreement": float(exp_agree) if has_exp else None,
        })
    scored.sort(key=lambda x: x["composite_score"])
    return scored

def build_verdict(ranked: list[dict], has_experimental: bool) -> str:
    """Human-readable one-liner for the executive summary card."""
    if not ranked:
        return "No ML comparisons available."
    best = ranked[0]
    if has_experimental:
        return (
```

```python
# Source: new HTMLReportGenerator helper
import plotly.io as pio
import plotly.graph_objects as go

class HTMLReportGenerator:
    def __init__(self, ..., plotly_js: str = "cdn"):
        self.plotly_js = plotly_js
        self._plotlyjs_emitted = False

    def _fig_to_div(self, fig: go.Figure, div_id: str) -> str:
        """Emit Plotly figure as HTML div. Only first call embeds plotly.js."""
        include = self.plotly_js if not self._plotlyjs_emitted else False
        self._plotlyjs_emitted = True
        return pio.to_html(
            fig,
            include_plotlyjs=include,
            full_html=False,
            div_id=div_id,
            config={"displaylogo": False, "responsive": True},
        )
```
