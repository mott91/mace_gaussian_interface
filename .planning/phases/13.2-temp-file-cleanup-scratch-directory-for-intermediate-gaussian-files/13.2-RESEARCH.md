# Phase 13.2: Temp File Cleanup -- Scratch Directory for Intermediate Gaussian Files - Research

**Researched:** 2026-03-12
**Domain:** File management, subprocess I/O isolation, ZMQ IPC path handling
**Confidence:** HIGH

## Summary

This phase moves all intermediate Gaussian files (.gjf, .log, .chk, .ipc_file) out of the project root into per-run scratch directories under `.scratch/`. The implementation is straightforward: create a scratch directory before each Gaussian run, pass it through the existing call chain, configure Gaussian's `%chk` path and IPC socket path to live inside the scratch dir, and add cleanup on success/failure with stale-dir auto-cleanup on startup.

The critical technical detail is how Gaussian resolves file paths. Gaussian 16 writes `.chk` files relative to its own cwd (the process cwd inherited from `subprocess.Popen`). Currently both `ase_to_gjf` and `create_gaussian_dft_input` write `%chk=` with a relative filename. The cleanest approach is to set `cwd=scratch_dir` on the Gaussian subprocess and write the `.gjf` into the scratch dir, so all intermediate files land there automatically. The IPC socket path must be absolute since `gm_helper.py` (invoked by Gaussian as a child process) needs to find it.

**Primary recommendation:** Create a `ScratchDir` context manager that handles directory creation, cleanup on exit, and stale-dir detection. Thread scratch_dir path through `run_frequency_calculation()` and `run_dft_baseline()`. Use `cwd=scratch_dir` in `subprocess.Popen` calls to keep all Gaussian output contained.

### Pattern: ScratchDir Context Manager

**What:** A context manager that creates the per-run scratch directory, provides its path, and handles cleanup on exit.

**When to use:** Wrap every Gaussian invocation (ML frequency and DFT baseline).

```python
# mace_gaussian/utils/scratch.py
import os
import shutil
import time
import logging
from pathlib import Path
from contextlib import contextmanager

logger = logging.getLogger(__name__)

SCRATCH_ROOT = ".scratch"
STALE_THRESHOLD_SECONDS = 24 * 3600  # 24 hours


@contextmanager
def scratch_dir(
    run_name: str,
    base_dir: str | Path = ".",
    keep_on_failure: bool = False,
):
    """Create a per-run scratch directory; clean up on exit.

    On normal exit (no exception): caller is responsible for moving
    files out before exiting the context. Directory is deleted.
    On exception: directory is deleted unless keep_on_failure=True.
    """
    scratch_root = Path(base_dir) / SCRATCH_ROOT
    scratch_root.mkdir(exist_ok=True)
    scratch_path = scratch_root / run_name
    scratch_path.mkdir(exist_ok=True)
    try:
        yield scratch_path
    except BaseException:
        if not keep_on_failure:
            shutil.rmtree(scratch_path, ignore_errors=True)
            logger.info("Cleaned up scratch dir: %s", scratch_path)
        else:
            logger.warning("Keeping scratch dir for debugging: %s", scratch_path)
        raise
    else:
        # Success path -- caller should have moved files out already
        shutil.rmtree(scratch_path, ignore_errors=True)


def cleanup_stale_scratch_dirs(base_dir: str | Path = ".") -> list[str]:
    """Remove scratch dirs older than 24 hours. Returns list of removed dirs."""
    scratch_root = Path(base_dir) / SCRATCH_ROOT
    if not scratch_root.exists():
        return []
    removed = []
    now = time.time()
    for entry in scratch_root.iterdir():
        if entry.is_dir():
            age = now - entry.stat().st_mtime
            if age > STALE_THRESHOLD_SECONDS:
                shutil.rmtree(entry, ignore_errors=True)
                removed.append(entry.name)
                logger.info("Removed stale scratch dir: %s (%.1f hours old)", entry, age / 3600)
    # Remove .scratch itself if empty
    if scratch_root.exists() and not any(scratch_root.iterdir()):
        scratch_root.rmdir()
    return removed


def list_stale_scratch_dirs(base_dir: str | Path = ".") -> list[tuple[str, float]]:
    """List scratch dirs older than 24h. Returns [(name, age_hours), ...]."""
    scratch_root = Path(base_dir) / SCRATCH_ROOT
    if not scratch_root.exists():
        return []
    stale = []
    now = time.time()
    for entry in scratch_root.iterdir():
        if entry.is_dir():
            age = now - entry.stat().st_mtime
            if age > STALE_THRESHOLD_SECONDS:
                stale.append((entry.name, age / 3600))
    return stale
```

### Pattern: Threading Scratch Dir Through Gaussian Calls

**What:** Pass `scratch_dir` path to the functions that create and run Gaussian files.

**For ML runs (workflow.py `run_frequency_calculation`):**
1. Create scratch dir with name like `run_{energy}_{dipole}_{timestamp}_{random}`
2. Write `.gjf` into scratch dir (pass `scratch_path / "gaussian_freq.gjf"` to `ase_to_gjf`)
3. Set IPC socket path to `scratch_path / "zmq.ipc"`
4. Set `MACE_IPC_PATH` env var before launching Gaussian
5. Pass `cwd=scratch_dir` to `run_gaussian_with_zmq` (which passes to `Popen`)
6. On success: move `.gjf`, `.log`, `.chk` from scratch to `freq_dir`

**For DFT runs (dft_baseline.py `run_dft_baseline`):**
1. Same scratch dir pattern
2. Write `.gjf` into scratch dir
3. No IPC needed (pure DFT, no ZMQ)
4. Pass `cwd=scratch_dir` to `run_gaussian_dft`
5. On success: move files from scratch to `freq_dir`

### Pattern: IPC Path via Environment Variable

**What:** `gm_helper.py` reads `MACE_IPC_PATH` env var instead of hardcoding `.ipc_file`.

```python
# gm_helper.py, line 28 modification:
if __name__ == "__main__":
    ipc_path = os.environ.get("MACE_IPC_PATH", ".ipc_file")
    with zmq_client(ipc_path) as socket:
        ...
```

The `MACE_IPC_PATH` env var is set in the Python process before launching Gaussian (Gaussian inherits the environment, and passes it to child processes like `gm_helper.py`).

### Anti-Patterns to Avoid

- **Changing Python process cwd with `os.chdir()`:** Never use `os.chdir()` to set Gaussian's working directory. Use `subprocess.Popen(cwd=...)` instead. `os.chdir()` is process-global and breaks concurrent runs.
- **Relative IPC path in scratch dir:** The IPC socket path passed to `GaussianZMQServer` must be absolute. The server runs in the main Python process (whose cwd is project root), but `gm_helper.py` runs in Gaussian's cwd (the scratch dir). Both need the same absolute path.
- **Using `tempfile.mkdtemp()`:** Don't use system temp dirs. The user decided on `.scratch/` under project root for visibility and debuggability.
- **Cleaning scratch dir BEFORE moving files on success:** The success path must move files out first, then delete. The context manager pattern handles this naturally -- the `else` branch runs after the caller's code.

## Integration Point Details

### 1. `gaussian/runner.py::run_gaussian_with_zmq()`

Currently: `subprocess.Popen(["g16", gjf_file], ...)` -- no `cwd` parameter.

Change: Add `cwd: str | Path | None = None` parameter, pass to `Popen`:
```python
proc = subprocess.Popen(
    ["g16", gjf_file],
    stdout=subprocess.PIPE,
    stderr=subprocess.PIPE,
    cwd=cwd,
)
```

The `gjf_file` should be just the basename (e.g., `"gaussian_freq.gjf"`) when `cwd` is the scratch dir, since Gaussian resolves it relative to cwd.

### 2. `gaussian/io.py::ase_to_gjf()`

Currently: writes `%chk={filename[:-3]}chk` -- relative to wherever the file is.

When `filename` is an absolute path like `/path/.scratch/run_xyz/gaussian_freq.gjf`, the `%chk=` will be `/path/.scratch/run_xyz/gaussian_freq.chk`. This is fine -- Gaussian handles absolute %chk paths correctly.

Alternative (simpler): write gjf with just a basename `%chk=gaussian_freq.chk` and rely on `cwd=scratch_dir` in Popen. This requires changing `ase_to_gjf` to write basename-only %chk when a scratch dir is in use. The simpler approach: pass `filename="gaussian_freq.gjf"` (basename) and write the file to `scratch_path / filename` by using `Path(scratch_path) / filename` as the actual open path.

**Recommendation:** Modify `ase_to_gjf` to accept an optional `output_dir` parameter. When provided, the file is written there and %chk uses the basename. This keeps the function clean.

### 3. `dft_baseline.py::run_gaussian_dft()`

Same pattern as runner.py: add `cwd` parameter to `subprocess.Popen` call.

### 4. `dft_baseline.py::create_gaussian_dft_input()`

Same as `ase_to_gjf`: currently writes `%chk={filename[:-4]}.chk`. Needs to write to scratch dir and use basename for %chk.

### 5. `gm_helper.py`

Critical change: read `MACE_IPC_PATH` env var with fallback to `.ipc_file`.

### 6. `cli.py::run()`

- Add `--keep-scratch` flag
- Read `MACE_KEEP_SCRATCH` env var as fallback
- Call `cleanup_stale_scratch_dirs()` at startup before running pipeline
- Pass `keep_scratch` through to `run_pipeline()`

### 7. `cli.py::diagnose()`

- Call `list_stale_scratch_dirs()` and report count + ages

## Naming Convention (Claude's Discretion)

**Recommended format:** `run_{energy_calc}_{dipole_calc}_{timestamp}_{short_random}`

Examples:
- ML: `run_mace_mp_espaloma_20260312_1430_a3f2`
- DFT: `run_dft_b3lyp_20260312_1430_b7c1`

The random suffix (4 hex chars from `os.urandom(2).hex()`) prevents collisions when the same calculator combo runs twice in the same minute. The timestamp format `%Y%m%d_%H%M` (minute granularity) keeps names readable.

## Stale Dir Age Detection (Claude's Discretion)

Use `Path.stat().st_mtime` (modification time). This is the simplest and most reliable approach:
- `st_mtime` updates when any file inside is written (indirectly, via the directory entry)
- Compare `time.time() - st_mtime > 24*3600`
- Works on all platforms

Alternative (creation time via `st_ctime` on Linux) is unreliable -- `st_ctime` is inode change time, not creation time. `st_mtime` is the right choice.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Scratch dir cleanup | Manual file tracking | Context manager with try/finally | Guarantees cleanup on any exit path including SIGINT |
| Temp directory names | UUID or complex schemes | Timestamp + short random hex | Readable, sortable, unique enough |
| Concurrent IPC isolation | Lock files or PID tracking | Per-scratch-dir IPC socket + MACE_IPC_PATH env var | Natural isolation, no coordination needed |

## Common Pitfalls

### Pitfall 1: Gaussian %chk Path vs Popen cwd
**What goes wrong:** If you write an absolute path in `%chk=` AND set `cwd=scratch_dir`, the .chk lands in the right place. But if you write a relative `%chk=foo.chk` and DON'T set `cwd`, the .chk lands in whatever the Python process cwd is.
**How to avoid:** Always use `cwd=scratch_dir` in Popen AND write basename-only `%chk=`. Both must agree.

### Pitfall 2: gm_helper.py Inherits Gaussian's cwd
**What goes wrong:** Gaussian runs `gm_helper.py` as a child process. It inherits Gaussian's cwd AND environment. If Gaussian's cwd is the scratch dir, `gm_helper.py`'s relative `.ipc_file` resolves to `scratch_dir/.ipc_file`, which is correct if the IPC socket is also there. But the ZMQ server runs in the main Python process with a different cwd.
**How to avoid:** Use absolute IPC path everywhere. `MACE_IPC_PATH` must be absolute. `GaussianZMQServer` already resolves to absolute via `Path(ipc_file).resolve()`.

### Pitfall 3: MACE_IPC_PATH env var leaking between runs
**What goes wrong:** If you set `os.environ["MACE_IPC_PATH"]` and a crash occurs before cleanup, the next run might inherit a stale path.
**How to avoid:** Set the env var only in the subprocess environment (via `env=` param to Popen) rather than modifying `os.environ` globally. OR use try/finally to restore.

### Pitfall 4: KeyboardInterrupt not caught by except Exception
**What goes wrong:** `KeyboardInterrupt` is a `BaseException`, not `Exception`. A bare `except Exception` in the move-files block won't catch Ctrl+C.
**How to avoid:** The `scratch_dir()` context manager catches `BaseException` (via the `except BaseException` pattern) for cleanup. Don't rely on inner exception handlers.

### Pitfall 5: formchk conversion in scratch dir
**What goes wrong:** After moving `.chk` to final location, `convert_chk_to_fchk()` is called. This still works because it uses the final path. But if formchk is called BEFORE the move (in scratch dir), the .fchk would be left behind.
**How to avoid:** Keep formchk conversion after the move, as it currently is.

### Pitfall 6: Gaussian log file path derivation
**What goes wrong:** Currently `log_temp = gjf_temp.replace(".gjf", ".log")`. With scratch dir, if `gjf_file` is a basename, `run_gaussian_dft` derives `log_file = gjf_file.replace(".gjf", ".log")` -- this is a relative path. With `cwd=scratch_dir`, Gaussian writes the log there, but the Python code needs to know the full path to find it.
**How to avoid:** After Gaussian finishes, construct the log path as `scratch_path / "gaussian_freq.log"` explicitly, don't rely on string replacement of the gjf path.

## Open Questions

1. **env= vs os.environ for MACE_IPC_PATH**
   - What we know: `env=` on Popen is cleaner (no global mutation), but `run_gaussian_with_zmq` currently doesn't accept an `env` param
   - What's unclear: Whether Gaussian passes the full inherited environment to external programs (it should, as standard subprocess behavior)
   - Recommendation: Use `env=` parameter on Popen. This is standard subprocess behavior -- child processes inherit the parent's environment. Add `env` parameter to `run_gaussian_with_zmq`.

2. **Should run_gaussian_with_zmq accept env or just cwd?**
   - What we know: We need both `cwd` and `env` (for `MACE_IPC_PATH`)
   - Recommendation: Add both `cwd` and `env` optional params to `run_gaussian_with_zmq`. Same for `run_gaussian_dft` (though DFT only needs `cwd`, not `env`).
