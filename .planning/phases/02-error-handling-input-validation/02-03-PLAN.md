**Version fix:**
- Change `@click.version_option(version="1.0.0", ...)` to `@click.version_option(version="0.2.0", ...)` to match pyproject.toml. This resolves the version inconsistency noted in research (pyproject.toml says 0.2.0, cli.py says 1.0.0).

**Validation integration in `run` command:**
- Add validation BEFORE the `from gm_main import run_workflow` import (validation should catch problems before expensive imports).
- Inside the `run()` function, after parsing calculator lists and before calling `run_workflow()`:

```python
# Validate prerequisites before expensive imports
from validation import (
    validate_all_prerequisites,
    validate_xyz_file,
    detect_device,
)
from exceptions import PrerequisiteError, InputValidationError

# 1. Validate input file
try:
    xyz_info = validate_xyz_file(str(input_path))
    click.echo(f"Input: {xyz_info['n_atoms']} atoms ({', '.join(set(xyz_info['symbols']))})")
except InputValidationError as e:
    click.echo(f"Error: {e}", err=True)
    sys.exit(1)

# 2. Validate prerequisites
try:
    prereqs = validate_all_prerequisites(
        check_gaussian=True,
        check_formchk_tool=True,
        dipole_model_path=None,  # Checked later by calculators
        helper_script_path=None,  # Checked later by gm_main
    )
    click.echo(f"Prerequisites OK: g16 found")
except PrerequisiteError as e:
    click.echo(f"Error: {e}", err=True)
    sys.exit(1)

# 3. Detect compute device
device = detect_device()
click.echo(f"Device: {device}")
```

- Place this block AFTER the input_path validation and BEFORE the `try: results = run_workflow(...)` block.
- The validation imports are lazy (inside the function), so `python cli.py list` and `python cli.py diagnose` will NOT trigger validation.
- Do NOT add validation to the `list`, `diagnose`, `compare`, or `export` commands -- they don't need Gaussian.

**Important:** Keep the existing `click.Path(exists=True)` on the `input_file` argument -- Click already checks file existence. The `validate_xyz_file` adds XYZ-specific validation (extension, parseability, atom count).

**Subprocess timeout (ERR-06):**

1. Add a module-level constant after the CONFIGURATION section (around line 78):
   ```python
   # Gaussian subprocess timeout (seconds)
   # Default: 24 hours for ML-assisted calculations
   # Override: Set GAUSSIAN_TIMEOUT_SECONDS environment variable
   GAUSSIAN_TIMEOUT_SECONDS = int(os.getenv("GAUSSIAN_TIMEOUT_SECONDS", "86400"))
   ```

2. In `run_frequency_calculation()`, after `proc = subprocess.Popen(["g16", gjf_temp])` (line 926), modify the ZMQ server loop to include timeout checking:
   - Add `calc_start_time = time.time()` before the `with zmq_server(...)` block
   - Inside the `while not is_calc_finished(proc, socket):` loop, add a timeout check BEFORE `msg = socket.recv_string()`:
   ```python
   # Check timeout
   elapsed = time.time() - calc_start_time
   if elapsed > GAUSSIAN_TIMEOUT_SECONDS:
       proc.kill()
       proc.wait()
       raise TimeoutError(
           f"Gaussian calculation timed out after {elapsed/3600:.1f} hours. "
           f"Increase timeout via GAUSSIAN_TIMEOUT_SECONDS env var "
           f"(current: {GAUSSIAN_TIMEOUT_SECONDS}s)."
       )
   ```
   - Place this check at the top of the while loop body, before the `logger.info` and `socket.recv_string()` calls.
