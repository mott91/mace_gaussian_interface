## Preface: Interface Requirements

**Energy calculator (ASE convention):** Any object settable as `atoms.calc` responding to
`atoms.get_potential_energy()` and `atoms.get_forces()`.

**Dipole calculator (thin custom base):** Must implement `calculate_dipole(atoms) -> (dipole_vector, partial_charges)`.
The `DipoleCalculatorBase.calculate_dipole_derivatives()` handles the finite-difference loop on top.
Wrapping any method that produces a dipole vector is ~1–2 hours.

**Already partially implemented but not exposed in CLI:**
- `mace_off` — implemented in `workflow.py::calculator()`, not in CLI `--energy-calculators` choices
- `mace_anicc` — available in the local `mace_ML_pkg` fork as `mace.calculators.mace_anicc`
- `xtb` (dipole) — fully implemented in `calculators/xtb.py`, registered in factory

## Energy/Force Calculators

### 1. MACE-OFF23 (mace_off)

- **Coverage:** H, C, N, O, F, P, S, Cl, Br, I — 10 organic elements. Trained on SPICE + DES370K (drug-like molecules, biomolecules). Not for materials.
- **ASE interface:** Native `MACECalculator`, identical to `mace_mp`. Already in `workflow.py::calculator("mace_off")`.
- **Accuracy vs DFT:** wB97X-D/def2-TZVPPD-level accuracy on conformational energies. Better than MACE-MP-0 for pure organic molecules.
- **Installation complexity:** Zero — in the already-installed local `mace_ML_pkg`. Model downloads on first use (~200 MB).
- **Integration effort:** ~1 hour — add `"mace_off"` to CLI choices in `cli.py`. Code already exists.
- **Scientific value for IR:** HIGH. Higher theoretical level training than MACE-MP-0 for organic chemistry. Most compelling near-zero-effort addition.
- **Verdict:** INCLUDE — almost free, highest scientific value

---

### 2. MACE-ANI-CC (mace_anicc)

- **Coverage:** H, C, N, O only — 4 elements. Trained on ANI coupled-cluster dataset (CCSD(T)/CBS energies for ~500k conformers of small organic molecules).
- **ASE interface:** Native `MACECalculator`. Available as `mace.calculators.mace_anicc` in the local fork.
- **Accuracy vs DFT:** Highest-accuracy small-molecule energy model in the repo for pure CHNO. Near-QM-quality energetics for conformational sampling.
- **Installation complexity:** Zero — already in `mace_ML_pkg`. Model file must exist on disk.
- **Integration effort:** ~1 hour — add to CLI choices, verify model file exists, add element guard.
- **Scientific value for IR:** HIGH for pure CHNO molecules (water, CO, NH3, formaldehyde, ethanol, acetic acid). Clean thesis question: "does CC-quality PES vs PBE improve IR frequencies?"
- **Known limitation:** Hard stops on any molecule with atoms outside CHNO.
- **Verdict:** INCLUDE — free (already in repo), scientifically important for thesis argument

---

### 3. xTB / GFN2-xTB (energy role)

- **Coverage:** All elements up to Z=86 (Rn) via GFN2-xTB.
- **ASE interface:** `xtb-python` (official): `from xtb.ase.calculator import XTB`. Already used in `calculators/xtb.py` for the dipole role. `tblite-python` is the actively maintained successor.
- **Accuracy vs DFT:** Semiempirical tight-binding, not ML. Geometries comparable to B3LYP/6-31G* for organic. Frequencies MAE ~50-100 cm⁻¹ vs experiment.
- **Installation complexity:** Low — `xtb-python` may already be installed in `mace4ir_v2`.
- **Integration effort:** ~2 hours — register in `calculator()` using `atoms.calc = XTB(method="GFN2-xTB")`.
- **Scientific value for IR:** MEDIUM. Useful as lower-bound baseline. Gives hierarchy: xTB → MACE-MP → MACE-OMOL → DFT. Very fast for debugging.
- **Verdict:** INCLUDE — already half-implemented, low effort, useful as lower-bound baseline

---

### 4. TorchANI / ANI-2x

- **Coverage:** H, C, N, O, F, S, Cl — 7 elements. Trained on ~9.5M conformers at wB97X/6-31G*.
- **ASE interface:** `torchani.models.ANI2x().ase()` — native, well-supported.
- **Accuracy vs DFT:** Good for drug-like CHNO+F/S/Cl. Not as accurate as mace_anicc for pure CHNO.
- **Installation complexity:** MEDIUM. `pip install torchani` — new dependency, ~100 MB model.
- **Integration effort:** ~3-4 hours — wrapper class, CLI addition, element check, tests.
- **Scientific value for IR:** MEDIUM-HIGH. Widely used community baseline; comparing ANI-2x vs MACE on IR is a strong thesis contribution. Coverage gap (no P, Br, I) limits molecule set.
- **Known limitation:** Last major TorchANI update ~2022; not actively developed.
- **Verdict:** DEFER — implement after zero-effort additions

## Dipole/Intensity Calculators

### 1. xTB GFN2 Dipoles (already implemented)

- **Approach:** GFN2-xTB Mulliken + CM5 charges.
- **Coverage:** All elements up to Rn.
- **Integration effort:** Zero — `calculators/xtb.py` is implemented and registered.
- **Scientific value:** MEDIUM-HIGH. Enables fully semiempirical baseline at near-zero cost.
- **⚠️ UNIT BUG WARNING:** `xtb.py` calls `atoms.get_dipole_moment()` without a unit conversion. `espaloma.py` explicitly divides by `BOHR_TO_ANGSTROM`. The `xtb-python` ASE interface returns dipoles in e*Angstrom (ASE convention). If `xtb.py` is missing a conversion, dipole derivatives will be wrong by a factor of ~1.89. **Verify before using in production.**
- **Verdict:** INCLUDE — already implemented, needs unit verification and a test

### 2. MBIS / DDEC6 / AM1-BCC Charges

All require DFT wavefunction as input — not standalone. **SKIP.**

### 3. Direct IR Intensity Prediction (end-to-end ML spectra)

Would bypass VPT2 entirely. Out of scope for this architecture. Worth mentioning as related work in thesis.
