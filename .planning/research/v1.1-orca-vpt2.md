## ORCA VPT2 Support

### Does ORCA support VPT2?

**YES — but as a recent addition with caveats.**

ORCA 5.0 (released 2021) introduced an anharmonic frequency module via `%VibCalc` block with the `Anharmonic true` keyword. ORCA 6.0 (~late 2024) significantly improved the anharmonic module. Feature is no longer listed as experimental but community adoption for production use remains lower than Gaussian's implementation.

**ORCA 4.x and earlier:** No VPT2 support. Harmonic frequencies only.

### Is ORCA freely available for academic use?

**YES** — free to download after registration (orcaforum.kofo.mpg.de). No license file or license server required. Commercial users must purchase a license. **Confidence: HIGH.**

## External Interface Mechanism

### Does ORCA have an equivalent to Gaussian's `external` keyword?

**NO — this is the central technical blocker. Confidence: HIGH.**

Gaussian's `external` mechanism: Gaussian calls an external program at each step → external reads fort.7 → returns energy/gradient/dipole/Hessian → Gaussian continues VPT2 using those values.

ORCA has no generalized "call external program for energy/gradient/dipole" hook. There is no `external` keyword in ORCA's input format. This is a known feature gap discussed in the ORCA community.

### The Core Problem: Dipole Derivatives

The current MACE-Gaussian architecture injects **dipole derivatives** into Gaussian's VPT2. ORCA computes dipole derivatives internally via finite differences — there is no input format for externally-supplied dipole derivatives going *into* ORCA's VPT2.

---

## Integration Architecture

Because ORCA has no `external` keyword, two paths exist:

### Path A: External Driver Wrapping ORCA
Python drives all geometry displacements, calls ORCA for QM quantities, calls ML for dipoles, assembles force constants numerically, then uses a VPT2 solver. Problem: you'd need a standalone Python VPT2 solver anyway, making ORCA redundant.

New modules required: `orca/runner.py`, `orca/io.py`, `orca/hessian.py`, `orca/vpt2.py`, `orca/dipole_derivatives.py`, major `workflow.py` changes, new parsers, new mode matching.

### Path B: Pure Python VPT2 (Cleanest Path)
Use MACE for energy/forces, ML dipole calculators for dipole moments at displaced geometries, Python VPT2 solver for anharmonic analysis. Eliminates both Gaussian and ORCA dependencies entirely.

Required: Python VPT2 library integration, numerical cubic/quartic force constants, validation against Gaussian reference results.

## Complexity Rating

**ORCA integration: VERY HARD**
**Pure Python VPT2: HARD**

### Key Technical Blockers

| Blocker | Severity | Notes |
|---------|----------|-------|
| No ORCA external hook | CRITICAL | No equivalent to Gaussian `external=` keyword |
| VPT2 must run somewhere | CRITICAL | If ORCA drives VPT2, ML injection is impossible. If Python drives VPT2, ORCA is redundant |
| Dipole injection mechanism | HIGH | ORCA computes dipole derivatives internally; no external input format |
| Output format rewrite | HIGH | All parsers assume Gaussian `.log`/`.fchk` — parallel ORCA implementations needed |
| Mode matching coupling | HIGH | `mode_matching.py` tightly coupled to Gaussian `.fchk` format |

## Alternative Open-Source VPT2 Options

### Psi4 (RECOMMENDED for investigation)
**License:** BSD 3-Clause, fully open source. Has a Python API (`psi4.energy()`, `psi4.gradient()`, `psi4.hessian()`). May be possible to provide a custom gradient and dipole function and have Psi4 drive finite differences, then run VPT2 — architecturally closer to the Gaussian `external` pattern than ORCA. **Confidence: MEDIUM** — needs verification against Psi4 docs.

### CFOUR
Best-in-class VPT2 implementation but no Python API, no external hook. Use only as validation reference. License restricts redistribution.

### PyVibTools / SNF
Standalone Python VPT2 solvers that take pre-computed force constants as input. Existence known from training data; maintenance status needs verification. **Confidence: LOW.**

## Recommendation

**Do not include ORCA integration in v1.1.**

The right question is not "ORCA or Gaussian" but "can we drive VPT2 entirely from Python?"

The most tractable open-source long-term path:
1. Use MACE for energy, forces, and Hessian (already works)
2. Use existing ML dipole calculators for dipole moments at displaced geometries
3. Use Psi4 or a Python VPT2 solver for VPT2 corrections from ML force fields

This would be a genuine scientific contribution: a fully ML-driven anharmonic IR pipeline with no QM code dependency.

| Option | Placement | Rationale |
|--------|-----------|-----------|
| ORCA integration | v2.0 or never | No external hook; would require ORCA developer cooperation |
| Psi4 investigation | v1.2 research task | Prototype whether Psi4 Python API accepts ML quantities for VPT2 |
| Pure Python VPT2 | v1.2 or v2.0 | Significant effort but cleanest path to open-source independence |
