## DFT Baseline Decoupling (SLURM)

### Architecture

```
Local machine                              HPC cluster (rune03)
1. run_geometry_optimization()
2. create_gaussian_dft_input() → .gjf
3. scp .gjf to cluster ──────────────────>
4. generate SLURM script (from qsub.sh template)
5. scp SLURM script ─────────────────────>
6. ssh: sbatch script.sh → capture JOB_ID
7. poll: ssh "squeue -j JOB_ID -h" (loop)   [g16 + formchk running]
8. scp back: .log, .fchk <───────────────
9. check "Normal termination" in .log
10. parse_gaussian_log() → save_frequency_results()
```

New module: `mace_gaussian/hpc/slurm.py` (~150 lines total). SSH/SCP via `subprocess` calls. The integration point in `workflow.py` is minimal: `run_dft_baselines()` gets a `use_cluster=True` branch.

**Important:** Add `formchk {basename}.chk {basename}.fchk` to the SLURM script itself — `formchk` must run in the same Gaussian environment that produced the `.chk`.

### Failure Modes

| Failure | Detection | Recovery |
|---------|-----------|----------|
| SSH connection refused | `returncode != 0` | Retry 3x with backoff, then raise |
| SLURM job failed | No "Normal termination" in `.log` | Mark `dft_failed`, continue batch |
| Job killed by walltime | `.log` ends abruptly | Increase `--time` in SLURM template |
| Network drop mid-scp | `scp returncode != 0` | Retry (remote files persist, idempotent) |
| `formchk` not on cluster | `.fchk` not created | Pull `.chk`, convert locally |

### Complexity: MEDIUM

Structurally clean (seam is designed in, `.gjf` generation exists, SLURM template proven). What's new: SSH/SCP wrappers (~50 lines), polling loop (~20 lines), error handling (~80 lines). MEDIUM because SSH subprocess management requires careful partial-failure recovery.

## Batch Molecule Workflow

### Design

**Sequential by default, overlapping DFT with nothing (cluster runs concurrent):**

```
Phase A (serial, local GPU):   optimize all N molecules
Phase B (parallel, cluster):   submit all N DFT jobs → poll until all complete
Phase C (serial, local GPU):   run ML freq calcs for all N molecules
Phase D:                        analysis + batch report
```

Wall time ≈ `N × t_opt + max(all DFT times) + N × t_ml_freq` — DFT runs concurrently while local machine is idle.

**Failure isolation via per-molecule status manifest:**

```json
{
  "batch_name": "organic_benchmark_v1",
  "molecules": {
    "aspirin":  {"status": "complete", "dft_job_id": "12345"},
    "acetone":  {"status": "dft_failed", "error": "walltime exceeded"},
    "methanol": {"status": "ml_calculating", "dft_job_id": "12347"}
  }
}
```

States: `pending → optimizing → optimized → dft_submitted → dft_done | dft_failed → ml_calculating → ml_done | ml_failed → complete`

On restart, skip `complete` molecules.

**CLI:**
```bash
mace-gaussian batch molecules.txt
mace-gaussian batch molecules.txt --dft-on-cluster rune03
mace-gaussian batch molecules.txt --skip-dft-baseline
```

`molecules.txt`: one XYZ path per line.

**Result structure:**
```
batch_results/{batch_name}/
  batch_manifest.json
  batch_summary.json        # aggregated R², RMSE per calculator pair
  batch_report.html         # multi-molecule extension of existing HTML report
  aspirin/
    geometry_opt/
    b3lyp_6-31Gdp/
    mace_mp_espaloma/
```

### Complexity: MEDIUM

Sequential loop over `run_pipeline()` with per-molecule try/except: ~30 lines (EASY). Manifest + state machine for recovery: ~100 lines. "Submit all DFT jobs, poll together" optimization: MEDIUM. Multi-molecule batch HTML report: MEDIUM.

## PubChem Structure Fetcher

### Library Recommendation

**Use `requests` directly against PubChem PUG REST API — not `pubchempy`.**

`pubchempy` adds a dependency without meaningful abstraction. PUG REST is simple:

```
GET https://pubchem.ncbi.nlm.nih.gov/rest/pug/compound/name/aspirin/SDF?record_type=3d
GET https://pubchem.ncbi.nlm.nih.gov/rest/pug/compound/cid/2244/SDF?record_type=3d
```

SDF→XYZ: `ase.io.read(sdf_file)` via RDKit backend (already installed):

```python
from ase.io import read, write
atoms = read("aspirin.sdf")
write("aspirin.xyz", atoms)
```

### Gotchas

1. **3D conformer availability** — `record_type=3d` returns HTTP 404 for ~15-20% of compounds. Fallback: generate from SMILES via RDKit `AllChem.EmbedMolecule()` + `MMFFOptimizeMolecule()`. Acceptable starting geometry since MACE re-optimizes.
2. **Protonation state** — PubChem stores neutral form. Fine for common organics; flag for amino acids and acids/bases with pKa ~7.
3. **Molecular charge** — extract `M  CHG` from SDF, pass to pipeline. Silently wrong otherwise.
4. **Multi-fragment structures** — detect disconnected components, take largest organic fragment or warn.
5. **API rate limiting** — ~5 requests/second. Add `time.sleep(0.2)` for N > 50 molecules.

### Complexity: EASY

Core fetcher ~50 lines. Gotcha handling adds ~50 more. No new heavy dependencies.

## Benchmark Molecule Set Design

### Literature Precedent

- **MACE-OFF23 paper (Batatia et al., 2023):** Benchmarks IR frequencies of drug-like molecules. Harmonic frequency RMSE and mode assignment — directly analogous to this workflow.
- **ANI-1/ANI-2x papers:** Benchmark IR frequencies of 10-20 small organic molecules per study.
- **VPT2 validation literature (Barone, Bloino groups):** Standard set: water, formaldehyde, acetaldehyde, formic acid, methanol, glycine — already in `comparison_results/`.
- **NIST WebBook:** Ground truth experimental gas-phase IR spectra. JCAMP-DX format. Available via HTTP. Directly usable for validation.

### Recommended Approach

**Two series, ~25 molecules total:**

**Series A: Size-scaling (10 molecules)**
Same functional group (alkanes, CH₄ → C₁₀H₂₂), increasing size. Shows ML vs DFT crossover cleanly. User already has `alkanes.sh` up to octane — extend to decane.

**Series B: Functional group diversity (~15 molecules, HCNO)**

| Ammonia | 4 | N-H | Yes |
| Formaldehyde | 4 | C=O aldehyde | Yes |
