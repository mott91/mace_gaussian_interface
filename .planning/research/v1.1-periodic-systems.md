## VPT2 Applicability to Periodic Systems

**VPT2 is categorically inapplicable to periodic systems.**

VPT2 is a molecular perturbation theory defined for finite, isolated systems with discrete normal modes. In periodic systems there are no discrete normal modes — only phonon branches labeled by wavevector **k**. The perturbation theory expansion is undefined for a system with translational symmetry.

**What periodic systems use instead:**

| Method | What it gives | Cost |
|--------|--------------|------|
| Harmonic phonons (DFPT) | Harmonic IR/Raman spectrum at Γ-point | Low-medium |
| AIMD + dipole autocorrelation | Anharmonic spectrum, includes all modes, finite temperature | Very high |
| VSCF/VCI on periodic potential | Quantum anharmonic corrections | High, rarely used |
| CRYSTAL17/23 periodic VPT2 | True VPT2 for periodic systems | Medium (unique capability) |

**CRYSTAL17/23 is the only QM code with a native periodic VPT2 implementation.** It uses an `ANHARM` keyword. This is a genuine niche capability — essentially no other production code supports it. Confidence: MEDIUM (verify at crystal.unito.it/documentation.php).

## QM Codes for Periodic Anharmonic Spectra

### CRYSTAL17/23
- **VPT2 / anharmonic support:** YES — `ANHARM` keyword, unique in the field
- **Periodic BC:** YES — primary purpose
- **ML injection mechanism:** None. No external program interface comparable to Gaussian's `external=`. Would need to be built from scratch with a different architecture than the current ZMQ approach.
- **License:** Academic free, commercial license required

### VASP
- **Anharmonic support:** Only via AIMD + Fourier transform of velocity autocorrelation. No VPT2.
- **Periodic BC:** YES — standard DFT plane-wave code
- **ML injection:** None
- **License:** Commercial (~€3,500+ per group)

### CP2K
- **Anharmonic support:** AIMD + dipole autocorrelation. No VPT2.
- **Periodic BC:** YES
- **ML injection:** i-PI coupling (velocity Verlet with external forces) — MACE has i-PI support. Not a dipole injection; would drive AIMD, not VPT2.
- **License:** GPL, free

### Quantum ESPRESSO
- **Anharmonic support:** DFPT harmonic + stochastic SSCHA for anharmonic FE. No VPT2.
- **Periodic BC:** YES
- **ML injection:** i-PI coupling similar to CP2K.
- **License:** GPL, free

### FHI-aims
- **Anharmonic support:** Harmonic via DFPT. Some VPT2 work ongoing in literature.
- **Periodic BC:** YES
- **ML injection:** None standard
- **License:** Academic free

## MACE Periodic Boundary Condition Support

**MACE already supports PBC at the graph level.**

From the codebase: `neighborhood.py` and `AtomicData` both accept `pbc` and `cell` arguments. The neighbor list construction handles minimum image convention. This is baked into the architecture.

**Which models support PBC:**
- **`mace_mp` (MACE-MP-0):** YES — trained on MPtrj dataset of periodic DFT trajectories (~1.5M structures from Materials Project). 89 elements including all transition metals. The correct choice for periodic systems.
- **`mace_omol` (MACE-OMOL-0):** LIKELY NO for periodic systems — trained on Open Molecules dataset (gas-phase molecular data). Not appropriate for bulk/surface.
- **`mace_off23`:** NO — molecular organic chemistry only, no periodic training.
- **`mace_anicc`:** NO — small molecule CC data, no periodic training.

**Confidence: MEDIUM** — `mace_mp` PBC training confirmed by dataset. `mace_omol` training data need verification from the MACE-OMOL-0 paper.

## Dipole Prediction in Periodic Systems

**Molecular dipoles (what `mace_ml` and `espaloma` compute) are physically ill-defined in periodic systems.**

In a periodic system, "dipole moment" depends on the choice of unit cell origin — it is not gauge-invariant. The physically meaningful quantity for IR intensities is the **Born effective charge tensor Z*_κ** (3×3 per atom), which measures how the macroscopic polarization changes with atomic displacement. Z* is computed via:

1. **DFPT** (standard, expensive) — perturb each atom, compute polarization response via Berry phase
2. **Finite differences of polarization** (slower but simpler to implement)
3. **ML Born charge prediction** (research frontier, 2023-2025) — equivariant GNN predicting Z* tensor per atom

For the current architecture, `espaloma` produces partial charges and `mace_ml` produces a molecular dipole vector. Neither concept transfers to periodic systems without fundamental reformulation.

**ML Born charge models:** Exist in the literature (2023-2025) but are not packaged as ready-to-use tools with broad elemental coverage. This would be a research contribution to build, not a software integration task.

## Architecture Delta

What would need to change to support even a simple periodic system (e.g., CO adsorbed on Pt surface):

| Component | Current | Periodic replacement |
|-----------|---------|---------------------|
| QM engine | Gaussian 16 (VPT2) | CRYSTAL23 (periodic VPT2) or CP2K (AIMD) |
| External interface | Gaussian `external=` keyword + fort.7 | None equivalent; build from scratch |
| ZMQ server | IPC socket, called by Gaussian | New IPC mechanism for new QM code |
| Energy calculator | mace_mp/mace_omol (already PBC-ready) | mace_mp (already works) ✓ |
| Dipole calculator | mace_ml/espaloma (molecular dipole) | Born charge ML model (doesn't exist ready) |
| Parser | gaussian/parser.py (`.log` format) | New parser for CRYSTAL23/CP2K output |
| Mode matching | fchk.py (Gaussian `.fchk` format) | Phonon eigenvectors from new format |
| Analysis | VPT2 peak positions | Phonon VDOS or VPT2 peaks (if CRYSTAL23) |

**Reusable from current codebase: ~15%** (MACE geometry optimization + the graph-level PBC handling).

This is thesis-appendix or future-paper territory.

## Pragmatic Middle Ground: Cluster Models

**Cluster models work with the current codebase today, zero changes required.**

A cluster model represents a periodic system as a large finite molecule: e.g., CO adsorbed on a Pt₁₃ cluster, a zeolite acid site as an H₈Si₈O₁₂ cage, a MOF linker fragment.

- **`mace_mp`** handles 89 elements including Pt, transition metals, Si — cluster models work out of the box
- **`mace_mp × espaloma`** or **`mace_mp × mace_ml`** can run the full pipeline
- Results are approximate (edge effects, no periodic electrostatics) but useful for: identifying whether ML gives reasonable geometry, testing frequency patterns, exploring method sensitivity
- Well-precedented in computational chemistry literature for surface site modeling

**Thesis framing:** "We validated on cluster models of [surface/MOF system] as a proof-of-concept for periodic-adjacent chemistry, while full periodic VPT2 support requires [CRYSTAL23 + Born charge ML] and is left for future work."
