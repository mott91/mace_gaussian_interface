## Problem

`mode_matching.py` implements `match_modes()` and `create_alignment_matrix()` — eigenvector-based mode matching via dot product overlap. These functions exist and work correctly. But `analyze_spectra.py` only imports `extract_mode_data_from_checkpoint` from that module — to pull frequencies from .fchk files. The actual eigenvector matching is never called from the analysis pipeline.

Mode-to-mode assignment in the analysis currently happens by frequency proximity (matching peaks in JSON results by closest frequency). For molecules where DFT and ML mode ordering diverges (e.g. modes swap order due to different PES curvature), this silently assigns the wrong modes to each other and corrupts all regression statistics — R², RMSE, MAE on both frequencies and intensities.

This is a silent correctness problem in the benchmark results.

## Solution

1. Read `analyze_spectra.py` carefully to understand where the mode-to-mode assignment currently happens.
2. At the point where ML and DFT frequencies are paired, replace proximity matching with eigenvector overlap matching using `match_modes()` from `mode_matching.py`.
3. The .fchk files for both DFT and ML runs should exist (they're generated by `convert_chk_to_fchk` in the workflow). Use those to extract eigenvectors.
4. Apply the match to correctly pair (ml_freq, ml_intensity) with (dft_freq, dft_intensity) before computing regression metrics.
5. Add a warning when match overlap is below threshold (currently 0.5) — these are mode assignments we're not confident about.
6. Verify on water and a larger molecule that the matched pairs make physical sense.
